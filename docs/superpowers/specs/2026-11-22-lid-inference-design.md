# Language identification by inference: design

Date: 2026-11-22. Base: `master` `47cb0ae` (3.6.2). Branch: `feat/lid-inference`.

## Problem

Wrong language detection produces false positives. The heuristic detector (`franc-min` plus lookup tables) is wrong
on 24 percent of the Tatoeba bench and 29 percent of short lines (comment at `src/content/pipeline.ts:298`). A wrong
answer either deletes a line the reader never sees (same-language skip, `ignoreEnglish`, source allowlist) or makes an
engine translate from a language the text is not in.

## Goal

Replace the heuristic guess with a trained model that ships inside the extension and runs for every user, on
Chrome, Firefox and Brave. No external service, no local runtime on the user's side: users only receive weights.
Chrome's built-in models (LanguageDetector, Gemini Nano) come second, only if a measured residual justifies them.

## Non-goals

Filtering lines without content, burst summaries, the per-channel budget, new lookup tables, any visible text or
new setting.

## Approach A: trained n-gram model in the bundle

### Data

- Tatoeba full public export, about 42 product languages, CC BY 2.0 FR (attribution in the README). The 5040
  sentences of the `langMatrix` bench are removed by hash of the normalized text; a test of the training script
  fails if one is injected.
- Real chat: the 28256 captured lines under the data folder (outside git), labeled only by the channel language,
  so noisy. Filters: lines without letters dropped, script must agree with the channel language, duplicates against
  dev and heldout removed. Added to training only if "Tatoeba + chat" beats "Tatoeba only" on dev.
- `dev` (1007 annotated chat lines) picks the model and the thresholds. `heldout` (993) is read once, at the end,
  with its sha256 checked before and after. Splits are by capture, never by line.
- No CC BY-SA data (OpenSubtitles frequency lists) in the shipped weights: the repo is MIT.

### Model

- Normalization: lowercase, NFKC, letter runs cut to 2, URLs and digits masked (mentions and emotes are already
  out of `realText`).
- Features: character n-grams 1 to 4 plus whole words, hashed into B buckets.
- Two candidates on dev: multinomial logistic regression on hashed features, and a fastText-style model (embedding
  of dimension d, mean, softmax). B and d swept. At equal cost (overlapping intervals) the simpler and smaller wins.
- Output: 42 languages plus `und`. Int8 weights, per-row scale. Temperature scaling (one scalar) fitted on half of
  dev, checked on the other half.
- Training in Python with numpy only, scripts in `tools/lid/`, fixed seed, data outside git.

### Integration

- Weights ship as a generated module inside `assets/content.js`: no manifest change, no web-accessible file. The
  weight audit baseline (`test/audits/audit_poids.py`) is raised in the same commit, with the exact byte count.
- Single entry point: the model replaces franc in `detectUncached`. Lookup tables keep priority. The CLD
  cross-check in `detectLanguageWithBrowser` stays.
- The model answers above a threshold `tau_det`, otherwise stays silent. That answer feeds the flag, filters,
  `ignoreEnglish` and the on-device engine source.
- `confidentLanguage` (the cloud `sl`) is extended to the model above its own threshold `tau_sl` only if that
  lowers the cost on dev and then on heldout. This is reported as a separate decision in the PR.
- Weights that fail to load or fail their checksum: behavior identical to `47cb0ae`, franc included, held by a test.
- `franc-min` is removed from the bundle if the model beats it in every length band; otherwise kept as fallback.
- Parity: the TypeScript inference matches numpy logits to 1e-4 on 500 lines (vitest, fixture generated by the
  training script).
- Counters under `__KT_METRICS__` only.

## Measurement

### Cost of an error (fixed before any measurement, not changed after seeing results)

| Event | Cost |
|---|---|
| Line deleted wrongly (same-language skip, source allowlist, `ignoreEnglish`) | 10 |
| Wrong `sl` sent to the cloud | 5 |
| Wrong source forced on the on-device engine | 4 |
| Wrong flag, no deletion | 1 |
| Silence (the cloud detects) | 0.5 |
| Right | 0 |

Simulated over readers targeting fr, es, pt, de, en, ru, tr, ar with default settings plus one reader with a source
allowlist. The simulator (`tools/lid/cost.py`) is checked against the real `prepare` on 50 lines (same decision per
line) before it is trusted. Thresholds minimize this cost on dev, per language when a language has at least 50 dev
lines, otherwise global.

### Baseline

Recomputed on `47cb0ae` for three paths: no browser API (Brave), Chrome CLD, Firefox CLD.

### Success criteria

- Cost per line lower on heldout for all three paths, bootstrap 95 percent interval (1000 draws, by capture) not
  containing zero. McNemar on paired errors reported.
- Wrongly deleted lines never up, for any reader target.
- Short band (20 characters or fewer) reported separately. ECE after calibration reported.
- p95 inference below 0.3 ms per line in the content script, release build. Added bytes and load time reported.
- A null result ships as such, with its error analysis.

## Approach B: Chrome built-in models, conditional

- Trigger: after A, measure on dev the share of lines A leaves below `tau_det` and their cost. Under 3 percent of
  lines or negligible cost: a PLAN.md entry with the numbers, nothing coded.
- Precondition checked first: the API answers from the content script (or the service worker, round trip measured)
  without any new permission. Otherwise B is dropped.
- LanguageDetector as a second opinion on ambiguous lines only. Then Gemini Nano on what is still ambiguous: micro
  batches (250 ms or 16 lines, whichever first), a session prepared at idle and cloned per batch, output constrained
  to the language codes, bounded delay. A late answer corrects only the flag, never a deletion. Enabled only for
  languages where Nano beats the model on dev (computed list).
- Presence detected at runtime. Firefox and Brave never touch B, held by a test.

## Delivery

Branch `feat/lid-inference`, each change with a test seen red then green, full gates once at the end,
`npm run build:firefox`, PR to `master` without merge, before/after table in the PR. Smoke test 15 minutes on
kick.com in a fresh anonymous profile before calling it done. Release is the maintainer's decision.
